# 샘플 프롬프트 (이미지 생성 마감 자동 채우기)

프롬프트 마감 시각까지 이미지를 확보하지 못한 플레이어(무제출·생성 실패·생성 지연)에게
서버가 여기 등록된 `{프롬프트, 이미지 URL}`을 랜덤 배정해 자동으로 채운다.

## 파일

- `sample-prompts.json` — 샘플 목록. 스타트업에 `SamplePromptProvider`가 인메모리로 적재한다.

## 형식

```json
[
  { "prompt": "노을 지는 해변을 걷는 강아지", "imageUrl": "https://<버킷>/samples/dog.jpg" }
]
```

- `prompt`: 해당 플레이어가 출제자가 되는 라운드의 **정답**이 되므로, 실제 유저가 썼을 법한 그럴듯한 한국어로 작성한다.
- `imageUrl`: 아래 절차로 S3에 올린 이미지의 공개 URL.
- 항목의 `prompt`/`imageUrl`이 비어 있거나 목록 전체가 비어 있으면 스타트업에서 즉시 실패한다.

## 샘플 추가 절차

1. 프롬프트에 어울리는 이미지를 준비한다(직접 제작하거나 게임의 생성 경로로 뽑아 저장).
2. S3의 `samples/` 프리픽스에 업로드한다. 생성 이미지(`generated-images/`)와 분리된 영구 정적 자산이다.
   ```bash
   aws s3 cp dog.jpg s3://<버킷>/samples/dog.jpg
   ```
   - 생성 이미지와 **동일한 공개 접근 경로**여야 플레이어 화면에 보인다. 버킷/CDN이 프리픽스로 접근을 제한한다면 `samples/*`도 공개 읽기에 포함시킨다.
3. 업로드한 이미지의 공개 URL을 `sample-prompts.json`에 `{prompt, imageUrl}`로 추가한다.

## 개수 권장

- 최소 1개 이상이면 동작하지만, 최대 인원(8명)이 동시에 이미지를 확보하지 못할 수 있으므로 실서비스에서는 8개 이상을 권장한다.
- 풀이 부족하면 같은 샘플이 여러 플레이어·라운드에 중복 배정될 수 있다(진행은 멈추지 않는다).
