# Application Code Guidelines

## 기본 규칙

- 패키지는 `com.igmo` 하위에 둔다.
- Spring 컴포넌트 의존성은 생성자 주입을 사용한다.
- Lombok은 필요한 애노테이션만 사용하고, 의미 없는 전체 생성 애노테이션은 피한다.
- TODO 주석을 남길 때는 연결된 이슈 번호를 함께 적는다.

## 가독성 규칙

- 메서드는 한 가지 의도를 드러내도록 작게 유지한다.
- 조건문이 길어지면 의미 있는 이름의 메서드로 분리한다.
- 변수명과 메서드명은 구현 방식보다 도메인 의미가 드러나게 작성한다.
- 주석은 코드로 의도가 드러나지 않는 정책, 제약, 예외 상황을 설명할 때만 사용한다.
- 같은 개념은 같은 이름으로 표현한다.

## YAGNI 기준

- 현재 요구사항에서 사용하지 않는 공용 추상화, 유틸 클래스, 설정 옵션은 만들지 않는다.
- 중복은 실제로 두 번 이상 반복되고 변경 이유가 같을 때 공통화한다.
- 별도의 지침이 없으면 과도한 이유로 인터페이스, 전략 클래스, 팩토리를 먼저 만들지 않는다.
- 새 의존성은 기존 Spring/JDK 기능으로 해결하기 어렵고 이점이 명확할 때만 추가한다.
